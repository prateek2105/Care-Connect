\begin{sectionbox}{MOTIVATION \& KEY IDEA}
\footnotesize
Object detection answers \textbf{what} objects are present and
\textbf{where}---core for robotics, autonomous vehicles, and
visual analytics. Its evolution is a repeated effort to push
the \textbf{speed--precision frontier} outward.

\smallskip
\textbf{Core tension:} mechanisms that raise accuracy (deeper
backbones, multi-scale fusion) also raise compute; efficiency
strategies can sacrifice spatial detail or semantic richness.

\textbf{Key takeaway:} the ``best'' detector depends on
deployment constraints---FPS, latency, power, memory, accuracy.
\end{sectionbox}

\begin{sectionbox}{EVOLUTION OF OBJECT DETECTION}
\footnotesize
\textbf{1) Traditional Era (pre-2012).}
Viola--Jones, HOG+SVM, and DPM used hand-crafted features with
sliding-window search. Effective on CPUs but limited by fixed
representations that could not generalize to diverse scenes.

\smallskip
\textbf{2) Deep Learning Shift (2012+).}
AlexNet proved CNNs learn hierarchical features end-to-end,
replacing manual descriptors and lifting the representation ceiling.

\smallskip
\textbf{3) Two-Stage Detectors (precision-first).}
R-CNN $\to$ Fast R-CNN $\to$ Faster R-CNN: generate candidate
regions first, then classify/refine each. Strong mAP, higher latency.

\smallskip
\textbf{4) One-Stage Detectors (speed-first).}
YOLO/SSD perform dense prediction in a single pass---fast, but
early versions lagged on small objects due to class imbalance.

\smallskip
\textbf{5) Focal Loss / RetinaNet (2017).}
Reweights easy negatives so training focuses on hard examples,
closing the mAP gap while preserving single-stage speed.

\smallskip
\textbf{6) Transformers / DETR (2020+).}
Set prediction via attention + Hungarian matching eliminates
anchors and NMS, enabling cleaner end-to-end pipelines.
\end{sectionbox}

\begin{sectionbox}{SOTA SNAPSHOT}
\footnotesize
\begin{itemize}
  \item \textbf{Faster R-CNN} (42.0 mAP, 26 FPS): best recall on
    small/occluded objects; heavy (246 GFLOPs, 60\,M params).
  \item \textbf{SSD512} (29.8 mAP, 61 FPS): lightweight and fast;
    weaker on small objects, limited multi-scale reasoning.
  \item \textbf{DETR} (42.0 mAP, 38 FPS): matches two-stage mAP
    with simpler pipeline; no anchors or NMS.
  \item \textbf{YOLOv8-L} (46.8 mAP, 97 FPS): best balanced point
    on the Pareto frontier; top choice for real-time deployment.
  \item Modern YOLO variants push both mAP \emph{and} FPS higher
    than previous alternatives.
\end{itemize}
\end{sectionbox}

\begin{sectionbox}{WHEN TO USE WHICH MODEL}
\footnotesize

\textbf{Rule of thumb:} FPS-critical $\Rightarrow$ YOLO;
mAP-critical $\Rightarrow$ Two-stage;
Simplicity $\Rightarrow$ DETR.
\end{sectionbox}

\begin{sectionbox}{CONCLUSION}
\footnotesize
\begin{itemize}
  \item Detection evolved: \textbf{hand-crafted} $\to$ \textbf{CNN}
    $\to$ \textbf{one-stage dense} $\to$ \textbf{transformer set prediction}.
  \item Progress $=$ shifting the Pareto frontier outward---higher
    mAP at same FPS or higher FPS at same mAP.
  \item The ``best'' model is deployment-dependent: latency, power,
    object scale, and acceptable error all determine the choice.
  \item Modern practice: start with \textbf{YOLOv8}; switch to
    \textbf{two-stage} for max mAP; use \textbf{DETR-style} for
    end-to-end reasoning.
\end{itemize}
\end{sectionbox}

\begin{sectionbox}{FUTURE DIRECTIONS}
\footnotesize
\begin{itemize}
  \item \textbf{Edge AI / TinyML:} INT8/INT4 quantization, pruning,
    knowledge distillation, hardware-aware NAS.
  \item \textbf{3D \& Multi-Modal:} camera--LiDAR fusion, Bird's-Eye
    View (BEV) representations for autonomous driving.
  \item \textbf{Open-Vocabulary Detection:} language-supervised
    grounding (GLIP, Grounding DINO) for novel categories.
  \item \textbf{Deployment-Aware Design:} FP16/INT8 inference,
    calibrated thresholds, domain-shift robustness.
\end{itemize}
\end{sectionbox}
