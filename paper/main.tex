\begin{abstract}
Object detection has evolved from handcrafted feature pipelines
and exhaustive search windows to end-to-end deep learning
systems capable of real-time operation.  This survey traces that
evolution: classical sliding-window detectors, the two-stage
deep detectors (R-CNN family) that introduced shared convolutional
features and region proposal networks, the one-stage detectors
(YOLO, SSD, RetinaNet) that reframed detection as dense
regression to achieve high frame rates, and the
transformer-based DETR paradigm that replaced heuristic
post-processing with bipartite set matching.  For each
architectural family we discuss key design decisions, trade-offs
on the speed--accuracy Pareto frontier, and the specific
problems that motivated the next generation of models.
\end{abstract}

\begin{IEEEkeywords}
object detection, convolutional neural networks, region proposal
network, YOLO, DETR, Pareto frontier
\end{IEEEkeywords}

\section{Introduction}

Object detection—the joint problem of \emph{localising} and
\emph{classifying} all instances of objects in an image—has been
a core challenge in computer vision for several decades.  The
difficulty stems from the need to handle extreme variation in
scale, viewpoint, illumination, occlusion, and background
clutter, while maintaining acceptable speed for practical
deployment.

Early solutions relied entirely on handcrafted image descriptors
and statistical classifiers.  The Viola--Jones detector
\cite{viola2001rapid} demonstrated that even simple Haar-like
features, when combined with a cascade of classifiers and the
integral image trick, could achieve real-time face detection on
2000s hardware.  HOG-based deformable part models
\cite{felzenszwalb2010object} later generalised this idea to
arbitrary object categories, remaining competitive until the
deep learning era.

Figure~\ref{fig:traditional_pipeline} illustrates the structure
of a classical detection pipeline.  The core steps—dense
sliding-window sampling, handcrafted feature extraction, and a
learned linear classifier—were shared across virtually all
pre-deep-learning detectors.  Their limitations (rigidity of
features, slow exhaustive search, limited generalisation)
motivated the shift to learned representations.

The survey is structured as follows.  Section~\ref{sec:dl}

Section~\ref{sec:onestage} covers one-stage detectors (YOLO,

transformer-based DETR architecture.  Section~\ref{sec:pareto}
analyses the speed--accuracy trade-off across all families.

\subsection{Evaluation Metrics}

The standard measure of detection quality is mean Average
Precision (mAP).  A detection is counted as a true positive if
its \textit{Intersection over Union} (IoU) with a ground-truth
box exceeds a threshold $\tau$:
\begin{equation}
  \mathrm{IoU}(B_p,B_{gt}) =
  \frac{\mathrm{Area}(B_p \cap B_{gt})}
       {\mathrm{Area}(B_p \cup B_{gt})}.
  \label{eq:iou}
\end{equation}
Equation~\eqref{eq:iou} ranges from $0$ (no overlap) to $1$
(perfect alignment).  COCO-style evaluation averages mAP over
$\tau\in\{0.50,0.55,\ldots,0.95\}$, penalising imprecise
localisation more strongly than the older Pascal VOC protocol
($\tau{=}0.50$).

\section{The Deep Learning Revolution}
\label{sec:dl}

The success of AlexNet \cite{krizhevsky2012imagenet} on
large-scale image classification demonstrated that convolutional
neural networks (CNNs), when trained with sufficient data and
compute, could learn feature representations that were both more
expressive and more transferable than classical hand-designed
descriptors.  For object detection, this shift meant the feature
extractor itself could be learned from data, enabling
representations that adapt to texture, shape, pose variation, and
background clutter.

\subsection{Two-Stage Detectors (Precision Pioneers)}

Two-stage detectors formalise detection as a \emph{candidate
filtering} problem.  Rather than classifying every possible
window, the first stage proposes a small set of regions likely
to contain objects; the second stage performs a more expensive
analysis on those regions to assign class labels and refine
localisation.  Figure~\ref{fig:twostage_pipeline} illustrates
the canonical two-stage workflow.

\subsubsection{R-CNN}

R-CNN \cite{girshick2014rich} was the first widely adopted
system to demonstrate large accuracy gains for detection via
CNN feature learning.  Its pipeline uses (i) Selective Search
\cite{uijlings2013selective} to generate $\approx$2\,000
category-agnostic candidate regions; (ii) per-region CNN forward
passes to obtain fixed-dimensional feature vectors; (iii)
class-specific linear SVMs for classification and a separate
regressor for box refinement.  While accurate, R-CNN's CNN had
to be executed once per proposal, making it impractical for
real-time use.

\subsubsection{Fast R-CNN}

Fast R-CNN \cite{girshick2015fast} reorganised computation by
running the CNN \emph{once} over the whole image to produce a
shared feature map.  A \textit{RoI pooling} layer then extracts
a fixed-size representation for each proposal.  This (i) reuses
convolutional work across all proposals, and (ii) enables joint
multi-task training of classification and box regression with a
single network.  The bottleneck shifted to the external Selective
Search proposal generator.

\subsection{Faster R-CNN and the Region Proposal Network}

Faster R-CNN \cite{ren2015faster} replaced Selective Search with
a learnable \textit{Region Proposal Network} (RPN) that slides
over the shared feature map and predicts objectness scores and
anchor refinements at each spatial location.  High-scoring
proposals feed the RoI classification head.  The entire system
can be trained end-to-end and runs on the GPU, removing the
CPU-bound bottleneck.

Despite these gains, Faster R-CNN retains the sequential
two-stage structure: Stage 1 must complete before Stage 2 can
begin.  RoI processing cost scales with the number of proposals
retained.  For crowded scenes or tight latency budgets, this
sequential structure becomes a ceiling.

\section{One-Stage Detectors: The Speed Revolution}
\label{sec:onestage}

One-stage detectors discard explicit region proposals and instead
treat detection as \textit{dense prediction}: the network
directly emits class confidences and box parameters at many
spatial locations in a single forward pass.
Figure~\ref{fig:onestage_pipeline} shows this workflow.  The
absence of a proposal stage maps well to GPU parallelism but
introduces a severe foreground-background class imbalance
(discussed in Section~\ref{sec:focal}).

\subsection{YOLOv1: Unified Grid-Based Prediction}

YOLOv1 \cite{redmon2016you} partitions the image into an
$S{\times}S$ grid.  Each cell predicts $B$ bounding boxes
(geometry + confidence) and $C$ conditional class probabilities,
yielding detections in a single network evaluation.  Global
image context is incorporated because the full image is seen
at once.  The grid responsibility assignment limits the model
to a small number of objects per cell, which motivated
subsequent improvements.

\subsection{SSD: Multi-Scale Feature Maps}

The Single Shot MultiBox Detector (SSD) \cite{liu2016ssd}
attaches lightweight detection heads to multiple feature maps at
different backbone depths.  Shallow maps (higher spatial
resolution) handle small objects; deep maps (large receptive
field) handle large objects.  Default boxes at multiple aspect
ratios and scales are defined per location, increasing the
variety of detectable shapes without a proposal stage.

\subsection{RetinaNet and Focal Loss}
\label{sec:focal}

One-stage detectors suffer from extreme class imbalance: the vast
majority of anchor positions are easy-to-classify backgrounds,
which swamp the gradient signal.  RetinaNet \cite{lin2017focal}
addresses this with \textit{Focal Loss} \eqref{eq:focal}:
\begin{equation}
  \mathrm{FL}(p_t) = -\alpha_t (1 - p_t)^\gamma \log(p_t),
  \label{eq:focal}
\end{equation}
where $p_t$ is the model's estimated probability for the correct
class, $\gamma{>}0$ is a focusing parameter, and $\alpha_t$
balances positive/negative examples.  Easy negatives ($p_t\to1$)
are down-weighted by $(1{-}p_t)^\gamma$, concentrating learning
on hard, informative examples.  RetinaNet matched two-stage
accuracy at competitive speeds, closing the mAP gap that had
held one-stage detectors back.

\subsection{The YOLO Family}

After the original YOLOv1, the YOLO line iterated rapidly.
YOLOv2/YOLO9000 \cite{redmon2017yolo9000} introduced
anchor-based prediction and multi-scale training.  YOLOv3
\cite{redmon2018yolov3} added a feature pyramid and a deeper
backbone.  YOLOv4 \cite{bochkovskiy2020yolov4} incorporated the
CSPDarknet backbone, PANet neck, and extensive data augmentation.
Later versions (v5--v8, including ultralytics variants) adopted
anchor-free detection heads, reparameterised backbones, and
task-aligned assignment strategies, continuing to push the
Pareto frontier.

\section{Transformer-Based Detection: DETR}
\label{sec:detr}

All detectors discussed so far rely on hand-designed
post-processing: anchor definitions, Non-Maximum Suppression,
and label-assignment heuristics.  DETR (DEtection TRansformer)
\cite{carion2020end} eliminates these components by casting
detection as a \textit{set prediction} problem solved via
bipartite matching.

Figure~\ref{fig:detr_pipeline} shows the DETR workflow.  A CNN
backbone extracts a feature map, which is flattened and passed
through a standard Transformer encoder.  The decoder receives
$N$ learned \textit{object queries} and attends to the encoder
memory, outputting $N$ box--class predictions.  At training
time, a \textit{Hungarian algorithm} matches predictions to
ground-truth objects with minimum cost, providing a unique
assignment that makes the loss permutation-invariant.

  \label{fig:detr_pipeline}

DETR's set-matching formulation is elegant but comes with
practical costs.  Training requires many more epochs to converge
than CNN detectors (typically 500 vs.\ 12--36) because the
object queries must learn to specialise.  Deformable DETR
\cite{zhu2021deformable} mitigates this via multi-scale
deformable attention, reducing complexity and greatly improving
convergence speed.  Subsequent variants (DAB-DETR,
DN-DETR, DINO-DETR) further close the gap with one-stage
detectors on both accuracy and speed.

\section{Speed–Accuracy Trade-off}
\label{sec:pareto}

A central design tension in object detection is the trade-off
between accuracy (mAP on COCO) and inference speed (FPS on a
fixed GPU budget).  Figure~\ref{fig:pareto} plots representative
models on this frontier.  Two-stage detectors (Faster R-CNN
variants) occupy the high-accuracy / lower-speed region.
One-stage detectors span a wide range: early YOLO generations
achieve very high FPS at modest mAP; RetinaNet and later YOLO
versions approach two-stage accuracy while maintaining
practical speeds.  DETR occupies a distinct region owing to
its Transformer backbone, which is compute-intensive but enables
superior cross-image reasoning.

The Pareto frontier has shifted significantly over time.  Early
two-stage detectors (R-CNN) would not even appear in
Figure~\ref{fig:pareto} due to their extremely low FPS.  The
introduction of the RPN (Faster R-CNN), Focal Loss (RetinaNet),
and anchor-free heads (FCOS, YOLOX) each pushed the frontier.
Current state-of-the-art detectors routinely exceed 50 mAP at
practical speeds, a target that seemed out of reach for most of
the past decade.

% CONCLUSION

\section{Conclusion}

This survey has traced object detection from exhaustive
sliding-window search (Figure~\ref{fig:traditional_pipeline})
through shared-feature two-stage detectors
(Figure~\ref{fig:twostage_pipeline}), dense one-stage
prediction (Figure~\ref{fig:onestage_pipeline}), and
bipartite set matching with Transformers
(Figure~\ref{fig:detr_pipeline}).  Each generation solved key
bottlenecks of its predecessor: two-stage detectors replaced
hand-crafted features with learned ones; one-stage detectors
removed the sequential proposal bottleneck; DETR eliminated
NMS and anchor engineering; and Focal Loss closed the
accuracy gap caused by class imbalance.

The speed--accuracy Pareto frontier (Figure~\ref{fig:pareto})
continues to move upward.  Open challenges include detection
under distribution shift, efficient deployment on edge
hardware, and extending set-matching ideas to video and 3-D
scenes.
